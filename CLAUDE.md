@AGENTS.md

## Project

**Arcade Vault** — plataforma para jugar online y competir por puntos. Currently a bare
`create-next-app` scaffold: only `app/layout.tsx`, `app/page.tsx`, `app/globals.css` exist.
There is no domain code, no database, no tests, and no CI yet — the game/scoring architecture
is still to be designed.

Product docs and issue discussion are in Spanish; code and identifiers in English.

## Commands

```bash
npm run dev     # next dev
npm run build   # next build
npm start       # next start (requires a prior build)
npm run lint    # bare `eslint` — flat config, no --dir/--ext args
npx tsc --noEmit   # typecheck (tsconfig has noEmit; no npm script for it)
```

No test runner is configured. Before adding tests, ask which runner is wanted rather than
assuming Jest/Vitest.

## Stack specifics that differ from older Next.js

Next **16.3.3** + React **19.2.8**, App Router only. Per `AGENTS.md`, read
`node_modules/next/dist/docs/` before writing framework code — that tree is the version-accurate
source of truth and overrides training-data assumptions. Layout is
`01-app/` (App Router), `02-pages/`, `03-architecture/`, `04-community/`.

- **Typed route props are global.** `layout.tsx` uses `LayoutProps<"/">`; pages use
  `PageProps<"/route">`. These are generated into `.next/types` (wired via `tsconfig.json`
  `include`), so they are ambient — do not import them, and do not hand-roll `{ params, searchParams }`
  interfaces. `params`/`searchParams` are Promises and must be awaited.
- **Tailwind v4, CSS-first.** No `tailwind.config.js` and none should be created. Design tokens
  live in `app/globals.css` under `@theme inline`; PostCSS is wired through
  `@tailwindcss/postcss` in `postcss.config.mjs`. Add a token to `@theme inline` to expose a new
  utility, don't reach for a JS config.
- **ESLint flat config** (`eslint.config.mjs`) composing `eslint-config-next/core-web-vitals`
  and `.../typescript` via `defineConfig`. The `globalIgnores` block re-states the defaults that
  the shared config would otherwise apply — keep those entries when editing.
- Path alias `@/*` maps to the repo root (not `src/`); there is no `src/` directory.
- Fonts come from `next/font/google` (Geist, Geist Mono) exposed as the CSS variables
  `--font-geist-sans` / `--font-geist-mono`, already bound to Tailwind's `--font-sans`/`--font-mono`.

The dark theme is driven by `prefers-color-scheme` in `globals.css` plus `dark:` utilities in
markup — there is no theme provider or `class`-based toggle.

## Workflow

The repo follows **spec-driven development** using the `/spec` and `/spec-impl` skills from
[Klerith/fernando-skills](https://github.com/Klerith/fernando-skills). If those commands are not
available in a session, install with:

```bash
npx skills@latest add Klerith/fernando-skills
```

`AGENTS.md` is regenerated by `next dev` (see
`node_modules/next/dist/server/lib/generate-agent-files.js`). Committing its changes alongside
your work is the intended behavior; reverting it just recreates the dirty file.
